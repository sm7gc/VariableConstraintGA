# DynamicShuffling

I made a simple modification to the Shuffling algorithm that dynamically selects candidates based on the level of constraint satisfaction. The algorithm first selects a child randomly from either the feasible or infeasible population. Then, the second child is dynamically selected based on the first child's constraint satisfaction. If the first child is feasible, the second child is selected from the feasible population. If the first child is near feasible (i.e., the percentage of constraints satisfied passes a threshold defined in the algorithm parameters), the second child is selected either from the near feasible or feasible populations. If the first child is infeasible, the second child is selected from the infeasible or (near) feasible populations.

This algorithm suffers from misspecification of the near feasible population threshold. In my cursory testing, I was not able to identify cases where the near feasible condition was met. An better approach might be to determine this threshold dynamically based on the top n% of satisfaction scores in the infeasible population. I don't expect this to perform better than the baseline Shuffling algorithm, but this was an interesting opportunity to explore genetic algorithm implementations in variable constraint problem spaces.
